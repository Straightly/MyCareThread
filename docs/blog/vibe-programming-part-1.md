# Vibe Programming: Building My Medical Records with AI

*Part 1 of a series on my experience with vibe programming*

## A Real-Life Use Case

I had a specialist appointment coming up in January for a chronic cough I've had for over two years. As a patient, I wanted what every patient wants: present my doctor with complete information, ask the right questions, and get the best results. As an experienced software developer armed with AI, I wanted to see what was possible—especially what I could build using the data access rights guaranteed by the 21st Century Cures Act.

I didn't know what problems I'd face, but I would learn as I went.

**My goal:** Build a Personal Medical Records application using the resources at my disposal: my development experience, AI tools built with billions of dollars, the advanced technology my doctors use, and the 21st Century Cures Act.

**My constraint:** I'm only entitled to my own records, but I want to build an application that is secure, flexible, extensible, and scalable—even though some capabilities will need additional work.

## What I Built

Over three weeks (December 7-26, 2025), I built a complete medical records application:

- **Backend:** Cloudflare Worker with KV storage (free tier)
- **Data pipeline:** Four-stage transformation from raw CDA XML → clean JSON → 850+ clinical concepts
- **Data model:** 8 concept types (Problem, Medication, Allergy, Procedure, VitalSignSet, LabPanel, Immunization, Encounter) optimized for AI consumption
- **Output:** Specialist briefing document with timeline, related conditions, medications, differential diagnosis, and organized questions

**All code generated by AI (Windsurf/Cascade). Zero lines written manually. Cost: $0.**

## Current Status

✅ **Done:** Gathered all records from my primary doctor, ingested them into my data model, and created a summary ready for my specialist.

⚠️ **Gaps discovered:**
- Records lack narratives. Even though I discussed symptoms with my doctor, they weren't recorded—probably not considered serious enough.
- Records from other providers are missing.

**Next steps:**
- Get insurance claims data to identify all care received
- Extend the app to pull records from all providers

## The Vibe Programming Workflow

### What I Stopped Doing: Writing AND Reading Code

Before I started, I knew I didn't want to write code. But early on, I still tried to read AI-generated code. I quickly realized this was counterproductive. The code was generally correct, followed reasonable patterns, and worked. Reading it line-by-line added no value.

**The mental shift:** I stopped being a code writer and became a problem solver. My new job: understand the problem, design the solution, break it into small steps for Windsurf to implement, and verify I got what I wanted.

### What I Started Doing: Project Plans and Verification

The project quickly became a communication challenge: telling Windsurf what to do and what not to do. I naturally evolved this workflow:

**1. Created PROJECT_PLAN.md**
- Broke project into phases (1-8)
- Each phase into steps (1.1, 1.2, 1.3...)
- Each step: goal, tasks, expected outcome, time estimate
- Marked steps complete only after verification

**Example from Phase 3:**
```markdown
- [x] Step 3.2 — Define Clinical Concept Types (1 hour)
  Goal: Identify all concept types to extract from CDA
  Tasks: Document Problem, Medication, Allergy, Procedure, etc.
  Outcome: CONCEPT_TYPES.md with 8 core types defined
  
- [x] Step 3.3 — Define Field Schema (1.5 hours)
  Goal: Specify fields for each concept type
  Tasks: Create FIELD_SCHEMA.md with examples
  Outcome: Clear schema for AI-optimized extraction
  
- [x] Step 3.4 — Extract Clean Clinical Concepts (2 hours)
  Goal: Transform CDA → clean JSON concepts
  Tasks: Implement conceptExtractor.js, deploy, verify
  Outcome: 850+ concepts extracted from 34 documents
```

**2. Verification Before Proceeding**

Never moved to the next step without verifying the current one worked. This meant:
- Running the code locally
- Deploying to Cloudflare
- Testing with real data
- Inspecting outputs
- Checking edge cases

**Example:** After implementing CDA ingestion (Step 1.5), I verified:
- All 34 documents uploaded successfully
- KV storage showed correct keys (`cda:DOC0001` through `cda:DOC0034`)
- Total size matched expectations (~13MB)
- Added `/debug/keys` endpoint to inspect KV contents

**3. Journaling Prompts and Actions**

I created `Journal/Journal-2025-12.md` and had Windsurf log:
- Every prompt I gave (verbatim)
- Every action taken
- Every decision made
- Every problem encountered

This created an audit trail and helped me understand what worked. It also became the basis for this article.

**4. Git as a Safety Net**

Vibe programming moves fast. Sometimes too fast. Git commits after each completed step meant I could always roll back when:
- AI misunderstood a requirement
- A refactoring went wrong
- I changed my mind about approach

Small, focused commits made it easy to revert without losing much work.

### When Windsurf is Humble

One of the most impressive moments came during a refactoring request. I asked Windsurf to rename a concept type across the entire codebase. After analyzing the scope, it responded:

> "This refactoring will require changes across 8 files with potential for errors between steps. I recommend using VS Code's built-in refactoring feature (F2 on the symbol) instead, as it will handle all references atomically."

I found this impressive because refactoring is one of Windsurf's strongest capabilities. It can restructure an entire codebase with a single prompt. Yet it knew when to recommend a better tool.

## What Didn't Work: The Model Comparison Detours

Mid-project, I got curious when Google's AntiGravity and Gemini 3.0 came out and decided to try them.

### AntiGravity
**Problem:** Could not reliably edit existing files without corrupting them. After a few failed attempts to make targeted edits, it would offer: "Would you like me to rewrite the entire file?"

For code files, this sometimes worked—if you don't mind massive git diffs. For record-keeping files (PROJECT_PLAN.md, Journal.md), it was disastrous: format preserved, but content lost or creatively invented.

### Google Gemini Pro 3.0 as Underlying Model in Windsurf
**Problem:** Would "run off" doing extensive work without clear communication. With a single prompt, it made changes across multiple files, added features I didn't ask for, and left me wondering: "What did it just do? Can I use this?" I switched back to Claude Sonnet and asked it to explain the code. Turned out mostly useful, but adapting it to my exact needs took more effort than starting fresh.

### Grok as Underlying Model
**Problem:** I used up my subscription credit a few days before month end, so I switched to the free Grok model. It didn't work—most of the instructions and code seemed copied from somewhere irrelevant.

## What Didn't Work Well: The Output Quality Gap

The specialist briefing document AI generated was good but incomplete.

**Strengths:**
- Comprehensive timeline extraction
- Correct identification of related conditions
- Reasonable differential diagnosis
- Well-organized question categories

**Weaknesses:**
- Missing context (some visits not in the data)
- Incorrect assumptions (based on incomplete information)
- Too many generic questions—presenting this list would produce an annoyed doctor, not a healthy patient 

**Why?** The AI could only work with the data I gave it. The CDA documents from my primary care doctor didn't include:
- Visits with other doctors
- My symptom descriptions—not much was recorded


## Key Lessons Learned

### 1. Vibe Programming Works—But Requires Expertise

I built a functional, deployed application with zero lines of manually written code. The AI handled backend architecture, data parsing, complex transformations, API design, refactoring, and deployment.

But it worked because:
- **I had to figure out what to build** (requirements engineering)
- **I had to verify correctness** (domain knowledge + testing)
- **I structured the work** (project planning)
- **I caught errors early** (step-by-step verification)
- **I had to choose the right tools** (Git, Cloudflare, VS Code)—AI will insist on building things even when they don't work  

I couldn't have built this without:
- **Software engineering experience:** Architecture, APIs, data modeling
- **Domain knowledge:** Healthcare data, CDA format, clinical concepts
- **Debugging skills:** Knowing how to unstick AI when it got stuck
- **Judgment:** What to build, what to skip, what to refactor

In other words: I still program, just using English instead of code.

### 2. Workflow and Tools

The tools mattered more than I thought. But what made vibe programming work was:
- Breaking work into verifiable steps
- Never letting AI do anything outside the plan
- Never proceeding without verification
- Journaling decisions for accountability
- Using Git for safety

### 3. AI Amplifies Your Inputs

The specialist briefing was only as good as the data I provided. Missing visits, symptom descriptions, and medication effectiveness meant incomplete output. AI doesn't fill gaps—it exposes them.
